# Cloudflare の準備と、iPhone での確認手順

あなた(ユーザー)にしかできない作業の手順です。手順は、2026-11-24 時点の Cloudflare 公式ドキュメントで確認しました。画面の表記が違う場合は、スクリーンショットを Claude に送ってください。

秘密情報(フィードURL、トークン、パスワード、ワンタイムコード)は、チャットにもこのリポジトリにも書かないでください。D1 の Database ID と Access の AUD タグは、秘密情報ではありません(それだけでは何もできません)。

## 手順1: アカウントと D1(今すぐできます)

1. [Cloudflare に登録](https://dash.cloudflare.com/sign-up)し、メールアドレスを確認します。二段階認証も有効にしてください。
2. **Workers & Pages** を開き、workers.dev のサブドメインを決めます。
   - 公開URLは `https://sabu6.<サブドメイン>.workers.dev` になります。
   - サブドメインは早い者勝ちです。あとから変えると、ホーム画面のアイコンと通知の許可を、夫婦それぞれがやり直すことになります。
3. **D1 SQL database** → **Create Database** を選びます。
   - 名前: `superapp`(D1 の名前。Worker 名の sabu6 とは別で、このままで問題ありません)
   - Location(任意): Asia-Pacific を選べる場合は、それを選びます。
4. 作成した D1 の **Database ID** を、Claude に伝えてください。Claude が `wrangler.jsonc` に書き込みます。

## 手順2: GitHub との連携(Claude が設定ファイルを更新し、main に取り込んだあと)

1. **Workers & Pages** → **Create** → GitHub のリポジトリを取り込む(Import a repository)を選びます。
2. 案内に従って、Cloudflare の GitHub アプリに、このリポジトリへのアクセスを許可します。
3. 設定は次のとおりです(画面の表記は日本語の場合)。
   - プロジェクト名: `sabu6`(`wrangler.jsonc` の name と同じにする。違うとビルドが失敗する。公式)
   - 本番のブランチ: `main`
   - ビルド コマンド: `npm run check`(型チェック、テスト、ビルド。テストが失敗すると公開されません)
   - デプロイ コマンド: `npx wrangler deploy`(既定のまま)
   - プレビューコマンド: 既定のまま(プレビュービルドをオフにするので使われません)
   - プレビュービルドを有効化: **オフ**。プレビューは、別に指定しない限り本番と同じ D1 を使います(公式)。このアプリは起動時に D1 の変更を適用するため、取り込み前の作業ブランチの変更が、本番のデータベースに入ってしまうからです。
   - Cloudflare Accessで保護: **オフのまま**。手順3で設定します(この画面では、2人のメールアドレスを個別に指定できないため)。
4. 最初のビルドが成功したら、公開URLを開きます。「表示できません(503)」と出れば、ここまでは正常です(まだログインの設定が無いため、わざと表示しない作りになっています)。

## 手順3: ログイン(Cloudflare Access)

1. **Zero Trust** を開き、チーム名を決めます。
   - Free プランを選びます。公式の説明では、Free プランでも支払い情報の入力が必要ですが、請求はされません。
   - チーム名は、ログイン画面のURL(`<チーム名>.cloudflareaccess.com`)になります。
2. 奥さまは Cloudflare アカウントを持っていないので、メールのワンタイムコードでログインできるようにします。
   - **Zero Trust** → **Integrations** → **Identity providers** → **Add new identity provider** → **One-time PIN**
3. **Workers & Pages** → `sabu6` → **Access** タブ → **Protect this Worker behind Access** を選び、**All traffic** を選びます。
   - この画面で選べる条件は「Cloudflare account」か「Email domain」だけです。いったん **Cloudflare account** で作成します。
   - Email domain(例: gmail.com)は選ばないでください。そのドメインのアドレスを持つ全員が入れてしまいます。
4. **Zero Trust** → **Access controls** → **Applications** で、作成されたアプリを編集します。
   - 許可の条件(ポリシー)を **Emails** にして、夫婦2人のメールアドレスを登録します。
   - ログイン方法に **One-time PIN** が含まれていることを確認します。
   - Session Duration は、選べる最長(1 month)にします。
   - **Additional settings** にある **Application Audience (AUD) Tag** を控えます(次の手順で使います)。
5. **Zero Trust** → **Access controls** → **Access settings** で、全体のセッション期間(global session duration)も最長(1 month)にします。

## 手順4: Worker に、ログインの検証用の値を設定する

**Workers & Pages** → `sabu6` → **Settings** → **Variables and Secrets** → **Add** で、次の2つを「テキスト」として追加し、**Deploy** を押します。

| 変数名 | 値 |
|---|---|
| `ACCESS_TEAM_DOMAIN` | `https://<チーム名>.cloudflareaccess.com` |
| `ACCESS_AUD` | 手順3で控えた AUD タグ |

公開URLを開き、メールアドレスを入れて、届いたコードでログインできれば完了です。ホームにカードが9枚並びます。

## 手順5: iPhone での確認(第1段階の目的)

夫婦それぞれの iPhone で行います。結果(できた/できなかった、表示された文言)を Claude に伝えてください。

**A. スーパーアプリ本体**
1. Safari で公開URLを開き、ログインします。
2. 共有ボタン → **ホーム画面に追加**。名前が「SABU6」、アイコンが紺色に白い点9つ、になっているか確認します。
3. ホーム画面のアイコンから開きます。ログインを求められたら、ログインできるか確認します(このときの画面の様子を教えてください)。
4. 右上の **設定** → **通知を有効にする** → 許可します。
5. 「開く画面」で **育児ログ** を選び、**テスト通知を送る** を押します。通知が届き、タップすると育児ログの画面が開くか確認します。

**B. 育児ログ単体のアイコン**
1. Safari で `公開URL/piyolog/` を開き、共有ボタン → **ホーム画面に追加**。名前が「育児ログ」、アイコンが黄色に白い円、になっているか確認します。
2. そのアイコンから開いたとき、ログインをもう一度求められるかを確認します。
3. 左上の **‹ ホーム** を押したとき、アプリの中でホームに移るか、別の画面(ブラウザのような画面)が開くかを確認します。
4. 設定画面の「起動したアイコン」が piyolog になっていることを確認します。

**C. 通知の許可が1回で済むか**
- A で許可したあと、B のアイコンからは許可を求められないこと。テスト通知は A の許可だけで届くこと。

**実機確認の結果(2026-11-25)と、その後の変更**
- A・B とも、ホーム画面のアイコンから開いたときにログインは求められなかった。B の「‹ ホーム」は、アプリの中でホームに移った。
- 名前は反映されたが、アイコンは A・B とも付かなかった。ログインなしでアイコンを取りに行くと Access のログイン画面に転送されるため、iPhone がアイコンを Cookie なしで取りに来ていると判断した。対策として、アイコンを HTML と manifest の中に直接埋め込むように変えた。
- A と B の両方で通知を許可すると、同じ通知が2通届いた(アイコンごとに別のアプリとして扱われるため)。対策として、通知を有効にできるのは A(本体)のアイコンからだけにした。B の設定画面では、ボタンが押せない。

**変更後の再確認**
1. A と B のアイコンを、ホーム画面から一度削除します(iPhone は、追加した時点のアイコンを使い続けるため)。
2. 手順 A-1・A-2 と B-1 を、もう一度行います。アイコンが付くかを確認します。
3. B を開き、**設定** の「通知を有効にする」が押せないこと、「起動したアイコン」が育児ログになっていることを確認します。
4. A で **テスト通知** を送り、通知が1通だけ届くことを確認します。登録済みの端末に、B から登録した古い宛先が残っている場合は、B の設定画面で「この端末の登録を解除」を押します。

## 第2段階の確認(設定、通知の基盤、並び順、アイコン)

マージして公開されたら、A(SABU6)で次を確認します。
1. **設定** に「共通の設定」(通知を避ける時間帯、エラー通知を受け取る)と「育児ログ」(通知を受け取る)が出ること。
2. 通知を避ける時間帯を追加・削除して **保存** できること(22:00〜06:00 のように日付をまたぐと「翌日」と表示される)。
3. **テスト通知** を送ると、**通知の履歴** に記録されること。
4. **ホームの並び順** で上下に動かして保存すると、自分のホームの並びだけが変わること(もう一方の端末は変わらない)。
5. **アイコン** で写真を選び、指でずらす・2本指で広げる・スライダーで大きさを変えて保存すると、ホームのカードのアイコンが変わること。
   ホーム画面に追加済みのアイコンは変わらないので、確認したい場合は追加し直します。

## 第3段階の確認(育児ログ)

**フィードURLの準備と保存**
1. ぴよログのアプリで、以前のフィードを失効させ、新しいフィードを作ります(「設定」→「データフィード」→「新しいフィードを作成」)。無料プランなら、取得期間は24時間、有効期限は90日です。
2. 「フィードURLを表示」→「URLをコピー」でコピーします。**URLはチャットなどに貼らないでください。**
3. SABU6 の **設定** →「育児ログ」の **フィードURL** →「入力する」で貼り付けて **保存** します。保存後は「設定済み」とだけ表示されます。
4. フィードを作った日が保存した日と違う場合だけ、「フィードの作成日(任意)」に作成日を入れます(期限の目安は作成日から89日)。

**動作の確認**
1. 5分以内に自動で取得されます。すぐに見たいときは、育児ログの画面の **今すぐ更新** を押します(1分に1回まで)。
2. 育児ログの画面で、授乳(前回の時刻と量、今日の回数と総量)、睡眠、おしっこ・うんちが、ぴよログの記録と合っているか確認します。
   - フィードで取得できるのは直近24時間の記録だけです。それより前の記録は、第4段階の「過去の記録の取り込み」で足せます。
   - 「いつもより」の比較は、記録が1日分そろった翌日から表示されます。
3. 通知を試すときは、設定の「授乳の通知の間隔」を一時的に短く(例: 30分)して、通知が届くか確認します。同じ記録については1回しか届きません。確認後は4時間に戻します。
4. CSV の書き出しは、第4段階で「データの管理」の画面に移りました(下を参照)。
5. ホームの「育児ログ」のカードに、「授乳 ○分前・おむつ ○分前」が出ることを確認します。

## 第4段階の確認(過去の記録の取り込み、CSV、比較、時間の帯)

**過去の記録の取り込み**
1. ぴよログのアプリで、取り込みたい月の「月ごとのテキスト」を書き出し、iPhone の「ファイル」に保存します。
2. 育児ログの画面のいちばん下の **データの管理(取り込み・CSV)** →「過去の記録を取り込む」の **テキストファイルを選ぶ** で、そのファイルを選びます。
3. 年月、日数、種類ごとの件数が表示されます。ぴよログの記録と合っていれば **○件を取り込む** を押します。
   - フィードで取得している期間(直近24時間)の記録は、フィードの記録を使うため、取り込みません。
   - すでに保存しているフィードの記録と、同じ種類・同じ時刻のものは、同じ記録として扱います(重なりません)。
   - 同じ月を何度取り込んでも、結果は同じです。途中で止まったときは、もう一度取り込めば正しく反映されます。
4. 「保存している記録」の件数と期間が増えたことを確認します。

**CSV**
1. 「データの管理」の **CSVを作る** → **保存・共有する** を押すと、iPhone の共有の画面が開きます。「"ファイル"に保存」を選ぶと保存できます。
2. 共有の画面を閉じても、アプリの画面に戻れることを確認します(以前は、ファイルの画面から戻れませんでした)。
3. CSV には、保存しているすべての期間の記録が入ります(フィードURLの期限が来ても、保存した記録は消えません)。

**メイン画面**
1. 授乳が、基準の時間(設定の「授乳の通知の間隔」、初期値4時間)を過ぎると、授乳の枠が赤くなり「基準の4時間を過ぎています」と出ます。
2. 授乳・睡眠・おむつの表で、「今日」と「ふだん」(過去7日の平均)を比べます。
   - 「今の時刻まで」の行は、過去7日それぞれの「0時から今と同じ時刻まで」の平均と比べます。
   - 「1日」の行は、今日の今までの値を、過去7日の1日分の平均と比べます(今日は途中なので、少なく出ます)。
   - 量と睡眠が、ふだんより少ないと、その行が赤くなり「少なめ」と出ます(数値そのものを比べます)。回数には出しません。
   - 設定の「授乳の1日の目安量」を入れると、授乳の「1日の量」は目安と比べ、届くまで「あと○ml」と出ます。
3. 「最近の記録」に、最後の体温・体重・身長・お風呂が出ます。その上に「室温・湿度」が出ます。
4. 「1週間の過ごし方」に、今日を含む7日分の帯で、睡眠・起きている時間・授乳・うんちが出ます。

**第4段階その2(2026-11-27)の確認**
1. 授乳・睡眠・おむつの3つが、ホーム画面のアプリで1画面に収まることを確認します。
2. 授乳の量は、棒で「今日」(棒)・「ふだん」(点線)・「目安」(太い線)を重ねて表示します。目安に届いていないと、棒が赤くなり「目安まであと○ml」と出ます。
3. 睡眠は「睡眠中 ○時間○分」または「活動中 ○時間○分」と出ます。活動中なら直前の睡眠の長さと「活動限界まであと○分」、睡眠中なら直前の活動の長さが出ます。
4. 活動限界(設定の「活動限界」、初期値3時間)を過ぎると、睡眠の枠が赤くなり、通知が届きます(起きた記録ごとに1回)。

**第4段階その4(2026-11-27)の確認**
1. 育児ログの画面の上の「‹ 前日」「翌日 ›」と、日付(押すとカレンダー)で、過去の日を表示できます。「今日」で今日に戻ります。
2. 過去の日は、その日1日分の授乳・睡眠・うんちを、その日より前の7日の平均(授乳は目安も)と比べます。室温・湿度は、その日の最低・最高・平均だけを出します。
3. 「1週間の過ごし方」は、表示している日を起点に7日分になります。
4. 今日の「室温・湿度」に、今日の最低・最高・平均が小さく出ます。
5. 室温・湿度の5分ごとの値は30日分だけ残し、それより古い日は1日ごとの最低・最高・平均にまとめます(5分おきの定期実行で、1回に1日分ずつ)。

**第5段階(グラフ、2026-11-27)の確認**
1. 育児ログの画面の上の **グラフ** を押すと、グラフの画面が開きます(「‹ 育児ログに戻る」で戻れます)。
2. 「日ごと(直近4週)」「週ごと(直近12週)」「月ごと(直近12か月)」を切り替え、「‹ ›」で期間を過去にずらせます。週ごと・月ごとの量・回数・睡眠は1日あたりの平均です。
3. 棒や点を押すと、その区切りの値が全部のグラフの右上に出ます。日ごとのときは「○/○ の育児ログを見る」で、その日の表示に移れます。
4. 初めて開いたときに「集計中です」と出ることがあります。1日ごとの集計を作りながら、少しずつ表示が増えます(定期実行でも少しずつ作るので、次からは速く出ます)。

**2026-11-27 の追加の確認**
1. 育児ログの画面を開いたとき、またはアプリが裏から戻ったときに、自動で最新の記録が表示されます(ぴよログ・SwitchBot へ取りに行くのは、夫婦の端末と定期実行を合わせて1分に1回まで)。
2. 授乳の枠に「次の目安 ○:○○(あと○分)」が出ます。ホームの「育児ログ」のカードにも「(次 ○:○○)」が出ます。

## 室温・湿度(SwitchBot)の準備と確認

室温・湿度は、育児ログの機能の一部です(ホームのカードはありません)。値は共通データにも保存するので、ほかの機能からも使えます。

1. SwitchBot のアプリで「プロフィール → 設定 → アプリについて」を開き、アプリのバージョンを10回たたくと「開発者向けオプション」が出ます。そこにある **トークン** と **クライアントシークレット** を使います(公式の説明: アプリ V9.0 以降の手順)。**値はチャットなどに貼らないでください。**
2. 育児ログの画面の右上の **設定**(または SABU6 の **設定** →「機能ごとの設定」→「育児ログ」)の「室温・湿度」にある **SwitchBot のトークン** と **SwitchBot のクライアントシークレット** に、それぞれ保存します。
3. 育児ログの **データの管理** →「室温・湿度(SwitchBot)」の **SwitchBot の機器を確認する** を押します。Hub 2 の行に「温湿度を読める機器 / ハブ本体」と出ることを確認します。
   - 機器が複数あって Hub 2 以外が使われるときは、設定の「室温・湿度を読む機器の名前」に、SwitchBot のアプリでの Hub 2 の名前を入れます。
4. 5分以内に、育児ログの画面のいちばん上に、室温と湿度が出ます(すぐに見たいときは「今すぐ更新」)。
5. 基準は、初期値が室温の下限 20℃、湿度の下限 40% です。上限は未設定です。設定画面で変えられます。基準の外になると、枠が赤くなります。
6. 通知は初期値オフです。設定の「室温・湿度の通知」(室温だけ・湿度だけ・両方)と「室温・湿度を通知するまでの時間」(0分ならすぐ)を選ぶと、基準の外の状態が続いたときに1回通知します。

## 困ったとき

- 画面に「表示できません(503)」: 手順4の変数が未設定です。
- 画面に「表示できません(403)」: AUD タグかチーム名が違う可能性があります。
- 通知が届かない: 設定画面の「登録済みの端末」の「直近のエラー」を Claude に伝えてください。
- 育児ログの画面に「取得に失敗」と出る: 表示された理由を Claude に伝えてください(URLは貼らないでください)。「フィードが見つかりません」なら、期限切れ・失効・URLの貼り間違いの可能性があります。
- ログが見たいとき: **Workers & Pages** → `sabu6` → **Logs**。
